# 任务边界判定与执行流程

本文件是**可执行检查清单**，在每次修改任务开始前使用。
长期原则见 `CLAUDE.md`。

---

## 1. 任务分级判定

在动手修改前，先回答以下问题，判定任务属于哪个区域：

### 快速判定表

| 问题 | 是 → 见 |
|---|---|
| 只是修一个明显的 bug（空指针、变量名错误、逻辑反转）？ | 绿区 |
| 只是增加一条错误提示或日志？ | 绿区 |
| 不影响协议字段、Redis key、认证流程、前端状态结构？ | 绿区 |
| 涉及 JSON 协议字段变更？ | 黄区 |
| 涉及 Redis key 或数据结构变更？ | 黄区 |
| 涉及连接认证/登录/重连流程变更？ | 黄区 |
| 涉及前端状态结构变更？ | 黄区 |
| 涉及多文件联动修改？ | 黄区 |
| 需要新增 service 文件？ | 黄区 |
| 要替换 WebSocket 框架？ | 红区 |
| 要重写整个前端或后端入口？ | 红区 |
| 要重建目录结构？ | 红区 |
| 要引入大型新依赖？ | 红区 |
| 要删除认证/ACK/去重/权限校验？ | 红区 |

### 判定规则

- **绿区**：说明计划 → 直接执行 → 修改后复盘
- **黄区**：输出方案（含影响范围和回滚方式） → **等待用户确认** → 执行 → 修改后复盘
- **红区**：输出方案 → **等待用户明确授权** → 执行 → 修改后复盘

不确定属于哪个区时，**按更高级别处理**。

---

## 2. 范围蔓延预警信号

执行过程中，如果出现以下信号，**立即暂停并重新评估**：

- [ ] 计划修改 1 个文件，实际需要动 3 个以上
- [ ] 发现需要同时修改前后端协议
- [ ] 发现需要改动 Redis key 设计
- [ ] 发现需要调整认证流程
- [ ] "顺便改一下"的冲动出现
- [ ] 修改影响了计划外模块的测试覆盖
- [ ] 用户提出新需求，偏离当前任务目标

出现任一信号时：停止当前修改，向用户说明发现了什么，请求重新确认范围。

## 3. 修改前声明模板

每次修改前，使用以下模板输出声明：

```
## 修改声明

**任务**：[一句话描述]

**分级**：绿区 / 黄区 / 红区

**涉及文件**：
- path/to/file1.py — [改什么]
- path/to/file2.js — [改什么]

**当前逻辑**：[简述现状]

**问题判断**：[为什么需要改]

**计划修改点**：[具体改什么]

**可能影响范围**：
- 协议字段：是 / 否（如果是，列出字段）
- Redis key：是 / 否
- 认证流程：是 / 否
- 前端状态结构：是 / 否
- 多节点行为：是 / 否

**回滚方式**：[如何撤销]
```

## 4. 修改后复盘模板

每次修改完成后，使用以下模板输出复盘：

```
## 修改复盘

**实际修改文件**：
- path/to/file1.py — [改了什么]
- path/to/file2.js — [改了什么]

**是否偏离计划**：是 / 否（如果是，说明原因）

**协议变更**：无 / [列出变更]

**Redis key 变更**：无 / [列出变更]

**认证逻辑变更**：无 / [列出变更]

**前端状态结构变更**：无 / [列出变更]

**手动测试方法**：
1. [步骤1]
2. [步骤2]
3. [步骤3]

**未解决风险**：无 / [列出]
```
