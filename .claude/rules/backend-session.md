# 后端修改前检查清单

本文件是**可执行检查清单**，用于修改后端连接、会话、认证、Redis、离线消息相关代码前逐项核对。
长期原则见 `CLAUDE.md` 第 5-7、9-10 节。

---

## 1. 连接与身份

在修改 `ConnectionContext`、`ctx.user_id`、登录逻辑前，逐项确认：

- [ ] `ConnectionContext` 的生命周期是否仍然清晰？新增字段是否有清理逻辑？
- [ ] `ctx.user_id` 的赋值和清除时机是否正确？是否存在静默覆盖？
- [ ] 已认证连接是否允许重新 login？策略是什么（拒绝/覆盖/先清理再登录）？
- [ ] 连接断开时，心跳任务、在线续约任务是否会被清理？
- [ ] 是否存在连接泄漏（任务未取消、引用未释放）？

## 2. 在线状态

在修改在线状态相关代码前，逐项确认：

- [ ] 在线状态何时设置？（登录成功后 / WebSocket 连接建立时）
- [ ] 在线状态何时清理？（连接断开时 / 进程退出时）
- [ ] Redis 在线状态 key 是否包含节点标识？清理时是否可能误删其他节点的在线状态？
- [ ] 同一用户多连接场景下，在线状态如何维护？

## 3. Redis 与离线消息

在修改 Redis 相关代码前，逐项确认：

- [ ] Redis key 前缀是否保持不变？如果必须改变，旧 key 如何迁移？
- [ ] 离线消息何时写入？（目标用户不在线时）
- [ ] 离线消息何时删除？（补发成功后 / 还是其他时机）
- [ ] 删除策略是否存在消息丢失风险？（补发失败但已删除）
- [ ] Pub/Sub 跨节点转发与本地连接投递是否区分清楚？
- [ ] 多节点场景下，消息是否会重复投递？去重逻辑是否仍然有效？

## 4. ACK 与去重

在修改 ACK 或去重逻辑前，逐项确认：

- [ ] `msg_id` 的生成方式是什么？唯一性如何保证？
- [ ] 去重窗口有多大？基于什么存储？
- [ ] ACK 超时后如何处理？（重发 / 丢弃 / 标记离线）
- [ ] ACK、离线消息、去重三者之间的关系是否仍然一致？

## 5. 多用户/多连接/多节点

在修改上述任何逻辑后，确认以下场景：

- [ ] 同一用户从两个节点分别连接，行为是否正确？
- [ ] 同一用户从同一节点建立两个连接，行为是否正确？
- [ ] 用户 A 在节点 1，用户 B 在节点 2，私聊消息是否正确路由？
- [ ] 节点宕机后，该节点的在线用户状态是否会被正确清理？

## 6. 错误处理与可观测性

- [ ] 登录失败是否有明确错误信息返回给客户端？
- [ ] 未认证连接发送消息是否有明确拒绝？
- [ ] Redis 异常是否有日志？是否会导致服务崩溃？
- [ ] WebSocket 异常断开是否有日志记录？
