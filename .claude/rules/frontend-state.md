# 前端修改前检查清单

本文件是**可执行检查清单**，用于修改前端调试页相关代码前逐项核对。
长期原则见 `CLAUDE.md` 第 8 节。

---

## 1. 客户端 A/B 隔离

本项目的调试页同时运行客户端 A 和客户端 B。修改任何状态相关代码前，逐项确认：

- [ ] 客户端 A 和 B 的连接实例是否独立？是否共享了同一个 WebSocket 对象？
- [ ] 客户端 A 的状态变更是否会意外影响客户端 B？
- [ ] 两个客户端的消息日志是否分别存储和展示？

## 2. Token 与用户身份

- [ ] token 是否按客户端分别保存（A 的 token 不进入 B 的请求）？
- [ ] 切换账号时，旧 token 是否被清除？
- [ ] 断开连接时，是否保留 token（以便重连）还是清除？
- [ ] 当前用户标识（user_id、username）是否按客户端隔离？

## 3. Conversation ID 隔离

- [ ] `room conversation_id` 是否按客户端 + 当前用户保存？
- [ ] `private conversation_id` 是否按客户端 + 当前用户 + 对方用户保存？
- [ ] 发送群聊消息时，使用的是否是当前客户端的 conversation_id？
- [ ] 发送私聊消息时，使用的是否是当前客户端的 conversation_id？
- [ ] 是否存在 A 创建的 conversation_id 被 B 使用的情况？

## 4. 状态清理时机

以下场景发生时，是否有明确的状态清理：

- [ ] 断开连接（点击 Disconnect）
- [ ] 切换账号（不刷新页面的情况下换用户登录）
- [ ] 重新登录（同一账号断开后重连）
- [ ] 后端返回会话归属错误（如尝试向未加入的房间发消息）

清理范围应包括：消息日志、conversation_id、在线状态显示、待发送队列。

## 5. 错误可见性

- [ ] 后端返回的错误信息是否在前端明确展示？
- [ ] 以下错误场景是否有可见提示：
  - [ ] 登录失败
  - [ ] 未认证发送消息
  - [ ] 会话不存在
  - [ ] 用户不属于会话
  - [ ] 私聊目标用户不存在或离线
- [ ] WebSocket 连接断开时是否有可见提示？
- [ ] 是否存在"操作执行了但前端没有反应"的情况？

## 6. 调试信息保留

- [ ] 是否保留了原始 JSON 收发日志展示？
- [ ] 日志是否包含时间戳？
- [ ] 日志是否区分发送/接收方向？
- [ ] 日志是否按客户端 A/B 分别展示？
- [ ] 错误消息是否在日志中可见？
